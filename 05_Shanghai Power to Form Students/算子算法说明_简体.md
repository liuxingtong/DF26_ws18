# 算子算法说明（简体）

本文档整理本项目中所有已注册的形态算子，说明它们如何从 `recs -> recs` 工作。对应代码主要位于：

- `engine/operators.py`
- `engine/my_operator.py`

## 0. 数据结构与公共约定

### 0.1 输入数据 `recs`

每个算子处理的基本单位都是一个记录 `rec`，典型结构为：

```python
{
  "geom": <shapely polygon>,
  "h": <height_m>,
  "sh": <stakeholder>,
  "frozen": <bool, optional>,
}
```

其中：

- `geom` 是建筑平面几何
- `h` 是建筑高度，单位为米
- `sh` 是利益相关者标签，如 `state`、`developer`、`resident`
- `frozen=True` 表示该对象后续不再被改写

### 0.2 默认筛选逻辑

在 `engine/operators.py` 中，多数基础算子都通过 `_aff(rec, target)` 判断对象是否生效：

```python
(rec["sh"] in target) and (not rec.get("frozen"))
```

也就是：

1. `sh` 必须命中 `target`
2. 不能被冻结

### 0.3 面积缩放的公共公式

若一个算子说“把 footprint 缩到原面积的 `ratio`”，它实际使用的是等比缩放：

```text
xfact = yfact = sqrt(ratio)
```

因此：

- 新面积 `A' = A * ratio`
- 若高度按守恒补偿，则常见写法是 `h' = h / ratio`

### 0.4 本项目中的 GFA 约定

项目里大量算子的直觉来自“近似保持单栋 GFA”：

```text
GFA ∝ footprint_area * height
```

因此如果平面面积变小，而高度按 `1 / ratio` 补偿，就近似保持单栋体量不变。

## 1. 基础算子（engine/operators.py）

### 1.1 `freeze(recs, who)`

代码位置：`engine/operators.py:32`

#### 作用

按 stakeholder 冻结对象，给后续算子划出“不可改写区”。

#### 算法

1. 复制 `recs`
2. 遍历每个 `rec`
3. 如果 `rec["sh"] in who`，则写入：

```python
rec["frozen"] = True
```

#### 更新内容

- 不改几何
- 不改高度
- 只改状态位 `frozen`

#### 输出效果

后续算子会跳过这些对象，常用于国家设施、遗产保护、居民核心等。

### 1.2 `weight_height(recs, weights, mode="conserve")`

代码位置：`engine/operators.py:41`

#### 作用

按 stakeholder 权重重分配高度。

#### 算法

1. 只取未冻结对象，记索引集合为 `idx`
2. 构造：

```text
w_i = weights.get(sh_i, 1.0)
a_i = area_i
h_i = height_i
```

3. 若 `mode == "grow"`：

```text
h_i' = h_i * max(1.0, w_i)
```

也就是只增不减。

4. 若 `mode == "conserve"`：

先计算：

```text
T = Σ(a_i * h_i)
S = Σ(a_i * h_i * w_i)
f = T / S
```

再更新：

```text
h_i' = max(h_i * w_i * f, 3.0)
```

其中 `f` 是归一化因子，用来让总量回到原始水平。

#### 更新内容

- 不改几何
- 改高度

#### 输出效果

- `conserve`：总量守恒，某些主体多拿高度，另一些主体让出高度
- `grow`：总量上升，权重大于 1 的主体获得增量

### 1.3 `concentrate(recs, center="state_centroid", reach_frac=0.18, state_boost=2.0, cap_m=600.0, min_h=5.0)`

代码位置：`engine/operators.py:74`

#### 作用

把高度向一个权力中心收拢，形成“中心隆起、外围退让”的单峰格局。

#### 算法

1. 计算场地总跨度：

```text
span = max(maxx - minx, maxy - miny)
lam = reach_frac * span
```

2. 计算中心点 `(Px, Py)`

- 若 `center == "state_centroid"`，则用 `state` 建筑按 `area * height` 加权求质心
- 否则用全体建筑按 `area * height` 加权求质心

3. 对每个未冻结对象计算：

```text
d_i = distance(centroid_i, (Px, Py))
boost_i = state_boost if sh_i == "state" else 1.0
w_i = boost_i * exp(-d_i / lam)
```

4. 再做一次守恒归一：

```text
T = Σ(a_i * h_i)
S = Σ(a_i * h_i * w_i)
f = T / S
h_i' = clip(h_i * w_i * f, min_h, cap_m)
```

#### 更新内容

- 不改几何
- 改高度
- 额外在输出里写入 `_center = (Px, Py, lam)`

#### 输出效果

越靠近中心的对象越高，越远越低；若中心是 `state_centroid`，则体现中央集权式的形态收拢。

### 1.4 `split_to_towers(recs, target, above_m2=1500, k=3)`

代码位置：`engine/operators.py:127`

#### 作用

把大 footprint 沿长轴拆成多个塔状单元。

#### 算法

1. 只处理满足以下条件的对象：

- 命中 `target`
- 未冻结
- `geom.area > above_m2`
- `k > 1`

2. 对每个目标建筑：

- 先求最小外接矩形 `minimum_rotated_rectangle`
- 识别最长边方向
- 令每个子塔的目标面积约为：

```text
area_each ≈ area / k
side = sqrt(area / k)
```

- 在长轴方向上均匀布置 `k` 个正方形
- 再旋回原来的角度

3. 每个有效子几何都会复制出一个新 `rec`

#### 更新内容

- 改几何：1 栋变 `k` 栋
- 不改高度

#### 输出效果

大体量被拆成多个小塔，栋数增加，平面更离散，常用于“开发主导的塔化前奏”。

### 1.5 `slim(recs, target, ratio=0.45)`


#### 更新内容

- 改高度

#### 输出效果

平面缩小，高度上升，单栋体量近似守恒，形态更接近细高塔。

### 1.7 `infill(recs, target, cell_m2=120, min_h=6, max_h=21, vary=0.35)`

代码位置：`engine/operators.py:159`

#### 作用

把大体量细分成大量小单元，形成低层、细粒度、自建感强的肌理。

#### 算法

1. 只处理满足以下条件的对象：

- 命中 `target`
- 未冻结
- `geom.area > 2 * cell_m2`

2. 设网格步长：

```text
step = sqrt(cell_m2)
```

3. 在原建筑的 bounding box 内做规则网格
4. 每个网格单元与原几何求交
5. 若交集面积大于 `0.28 * cell_m2`，再做一次负缓冲：

```text
piece = piece.buffer(-step * 0.06)
```

6. 对每个有效子片段 `pp`：

- 若面积小于 `0.18 * cell_m2`，丢弃
- 否则生成新对象

7. 高度由一个确定性伪随机变量控制：

```text
v = ((ci * 7 + 11) % 100) / 100
h_raw = min_h + (max_h - min_h) * (0.5 + vary * (v - 0.5)) * v
h' = clamp(h_raw + min_h, min_h, max_h)
```

#### 更新内容

- 改几何：1 栋可能变多栋
- 改高度：每块高度不同

#### 输出效果

大体量被打碎成许多低层小单元，颗粒度显著上升。

### 1.8 `level(recs, target, toward="median", alpha=0.6)`

代码位置：`engine/operators.py:191`

#### 作用

让目标建筑高度向某个参考值靠拢。

#### 算法

1. 收集所有目标对象当前高度 `h_i`
2. 计算参考高度 `ref`

- `toward == "median"` 时：

```text
ref = median(h_i)
```

- 若 `toward == "p40"` 这类字符串：

```text
ref = percentile(h_i, 40)
```

- 否则把 `toward` 当作直接数值

3. 对每个目标对象更新：

```text
h_i' = h_i + alpha * (ref - h_i)
```

#### 更新内容

- 不改几何
- 改高度

#### 输出效果

高度差被拉平，`alpha` 越大，整体越均质。

### 1.9 `scale(recs, target, factor=2.0)`

代码位置：`engine/operators.py:209`

#### 作用

按几何中心整体放大或缩小 footprint。

#### 算法

对每个目标对象：

```text
geom' = aff.scale(geom, xfact=factor, yfact=factor, origin="centroid")
```

因此：

- 长度尺度乘 `factor`
- 面积乘 `factor^2`

#### 更新内容

- 改几何
- 不改高度

#### 输出效果

平面尺度整体变化，面积和体量容量一起变化。

### 1.10 `scale_graded(recs, target, center="global_centroid", factor=2.0, reach_frac=0.25, min_factor=1.0)`

代码位置：`engine/operators.py:219`

#### 作用

按到中心点的距离，渐变地放大或缩小 footprint。

#### 算法

1. 求场地跨度：

```text
span = max(maxx - minx, maxy - miny)
lam = max(reach_frac * span, 1e-6)
```

2. 求中心 `(Px, Py)`，方式与 `_center()` 相同
3. 对每个目标对象：

```text
d = distance(centroid, center)
g = exp(-d / lam)
f = min_factor + (factor - min_factor) * g
geom' = scale(geom, xfact=f, yfact=f, origin="centroid")
```

#### 更新内容

- 改几何
- 不改高度

#### 输出效果

靠近中心的对象变化更强，远离中心的对象变化更弱，形成连续梯度。

```text
h' = min(h / stretch, cap_m)
```

- 改几何
- 改高度

## 3. 打浦桥专属算子（engine/my_operator.py）

这组算子依赖 `_copy_with_tags()` 先给建筑补空间标签。

### 3.1 `_copy_with_tags()` 补标签规则

虽然它不是外部算子，但理解后面 5 个打浦桥算子必须先知道它的规则。

对每个 `rec`：

- 若 `sh == "resident"`：
  - 加 `residential_core`
  - 每 5 个加 1 个 `resident_gate`
- 若 `sh == "state"`：
  - 加 `emergency_access`
- 若 `sh == "developer"`：
  - 加 `tourism_frontage` 与 `commercial`
  - 若面积 `< 220`，再加 `micro_shop`
  - 每 7 个加 1 个 `culture`
- 若面积 `< 180` 且 `sh in ("resident", "developer")`：
  - 加 `heritage`

所以这套标签不是外部 GIS 真值，而是教学情景中的规则化空间角色层。

### 3.2 `freeze_tags(recs, tags)`

2. 遍历每个对象
3. 只要 `rec` 的标签与输入 `tags` 有任意交集，就设：

```python
rec["frozen"] = True
```

#### 更新内容

- 不改高度
- 只改冻结状态

#### 输出效果

可把遗产、居民核心、消防通道等固定下来。

### 3.3 `micro_lease(recs, target, above_m2=500, cell_m2=80, affordable_ratio=0.35, local_service_ratio=0.20, culture_ratio=0.15, min_h=6, max_h=18, seed=42)`

代码位置：`engine/my_operator.py:153`

#### 作用

把大商业体量拆成大量小租赁单元，并按比例分配不同经营类型。

#### 算法

1. 先补标签
2. 只处理满足以下条件的对象：

- `sh in target`
- 未冻结
- `geom.area > above_m2`

3. 网格步长：

```text
step = sqrt(cell_m2)
```

4. 在 bounding box 上做网格，与原几何求交
5. 若交集面积大于 `0.25 * cell_m2`，则负缓冲：

```text
piece = piece.buffer(-step * 0.04)
```

6. 仅保留：

```text
piece.is_valid and piece.area > 0.12 * cell_m2
```

7. 打乱所有片段顺序 `rng.shuffle(pieces)`
8. 对第 `i` 个片段分配高度：

```text
v = ((i * 13 + seed) % 100) / 100
h' = min_h + (max_h - min_h) * v
```

9. 用片段序号比例：

```text
q = i / n
```

来分配经营属性：

- 若 `q < affordable_ratio`
  - 加 `affordable_micro`, `micro_shop`
  - `sh = "developer"`
- 若 `q < affordable_ratio + local_service_ratio`
  - 加 `local_service`, `micro_shop`
  - `sh = "resident"`
- 若 `q < affordable_ratio + local_service_ratio + culture_ratio`
  - 加 `culture`, `micro_shop`
  - `sh = "state"`
- 否则
  - 加 `tourism_frontage`, `micro_shop`

#### 更新内容

- 改几何：大体量被拆成多个小单元
- 改高度：小单元高度在低层范围内变化
- 改 `sh` 和 `tags`

#### 输出效果

从“大商业块”转向“细粒度、小租赁、混合功能单元”。

### 3.4 `frontage_quota(recs, primary_routes="tourist_spine", frontage_buffer_m=8, max_tourism_ratio=0.45, min_local_service_ratio=0.15, min_micro_shop_ratio=0.25, min_culture_ratio=0.15, seed=42)`

代码位置：`engine/my_operator.py:205`

#### 作用

控制游客主界面的功能配额，避免旅游消费一边倒地占满 frontage。

#### 算法

1. 先补标签

3. 把满足以下条件的对象视为 frontage：

```text
distance_to_spine <= frontage_buffer_m
```

4. 将 frontage 索引打乱
5. 对 frontage 总数 `n` 计算最低保留配额：

```text
local_service_count = ceil(n * min_local_service_ratio)
micro_shop_count   = ceil(n * min_micro_shop_ratio)
culture_count      = ceil(n * min_culture_ratio)
```

6. 按顺序给前几批 frontage 分配：

- `local_service`，同时 `sh = "resident"`

7. 找到所有仍带 `tourism_frontage` 的 frontage
8. 允许保留的旅游界面数：

```text
allowed = floor(n * max_tourism_ratio)
```

9. 超额部分会：

- 去掉 `tourism_frontage`
- 改加 `shared_frontage`

#### 更新内容

- 不改几何
- 不改高度
- 改 `sh` 和 `tags`

#### 输出效果

沿街界面的功能更均衡，保留居民服务、小店和文化展示位。

### 3.5 `crowd_valve(recs, route="tourist_spine", crowd_threshold=0.75, one_way_links=True, protect_tags=None, relief_nodes=3)`

代码位置：`engine/my_operator.py:246`

#### 作用

在游客高峰期对主线附近商业界面做减压，为疏散和通行让出空间。

#### 算法

1. `protect_tags` 默认为空列表
2. 先补标签
3. 若：

```text
crowd_threshold < 0.5
```

则直接返回，不做处理

4. 用 `_site_axis()` 求主轴
5. 候选对象必须同时满足：

- 未冻结
- 不命中 `protect_tags`
- 带 `tourism_frontage`
- 到主轴距离 `<= 18`

6. 候选对象按 `geom.area` 从大到小排序
7. 对第 `i` 个候选：

- 若 `i < relief_nodes`

```text
geom' = scale_area(geom, 0.72)
h'    = min(h / 0.72, 24)
```

并加 `relief_node`

- 否则

```text
geom' = scale_area(geom, 0.90)
h'    = min(h / 0.90, 30)
```

8. 若 `one_way_links=True`，则再加 `one_way_alley`

#### 更新内容

- 改几何：主线附近商业 footprint 收缩
- 改高度：守恒补偿后限高
- 改标签

#### 输出效果

### 3.6 `night_reversion(recs, start_hour=22, quiet_buffer_m=10, commercial_shutdown_ratio=0.60, protect_tags=None)`

代码位置：`engine/my_operator.py:272`

#### 作用

在夜间把靠居民核心的部分商业和游客空间收回，归还给安静生活与居民通行。

#### 算法

1. 先补标签
2. 找出所有带下列标签的居民核心参照：

- `residential_core`
- `resident_gate`

3. 若一个都没有，直接返回
4. 遍历每个对象，只处理满足以下条件者：

- 未冻结
- 不命中 `protect_tags`
- 带 `commercial` 或 `tourism_frontage`

5. 计算该对象质心 `c` 到任意居民核心质心的距离
6. 若存在：

```text
distance(c, resident_centroid) <= quiet_buffer_m
```

则视为夜间需回收对象

7. 给它加：

- `night_quiet`
- `resident_return`

8. 计算保留比例：

```text
keep = max(1.0 - commercial_shutdown_ratio, 0.15)
```

默认参数下：

```text
keep = max(1 - 0.60, 0.15) = 0.40
```

9. 先调用 `_scale_area`：

```text
geom' = scale_area(geom, keep)
h_tmp = min(h / keep, 18)
```

10. 然后再次压低高度：

```text
h' = max(h_tmp * keep, 3.0)
```

默认情况下相当于把经过补偿的高度再乘一次 `0.40`。

#### 更新内容

- 改几何：夜间商业 footprint 显著缩小
- 改高度：最终也被压低
- 改标签

#### 输出效果

夜间靠近居民核心的消费空间被大幅收缩，形成“空间归还”和“降噪”。

## 5. 如何阅读一条配方

`regimes.yaml` 里的一条体制，本质上就是这些算子的顺序组合：

```yaml
steps:
  - { op: freeze, who: [state] }
  - { op: split_to_towers, target: [developer], above_m2: 1200, k: 2 }
  - { op: slim, target: [developer], ratio: 0.82 }
  - { op: densify, target: [developer], far_gain: 1.10, cap_m: 36 }
```

阅读时建议按这个顺序理解：

1. 先看谁被冻结
2. 再看谁被选为目标对象
3. 再看平面是被拆分、缩小、拉长还是放大
4. 最后看高度是被守恒补偿、整体抬高，还是被拉平

这样就能把“权力体制”翻译成“形态生成逻辑”。
